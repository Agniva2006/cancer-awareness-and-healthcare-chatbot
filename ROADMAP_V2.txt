PHASE 6: MULTIMODAL VISION -- CNN + ViT CROSS-MATCHING ENGINE
================================================================================
Philosophy: SIMPLE. Two small models that AGREE or DISAGREE, bridged by the
chatbot you already have. No 3D pipelines. No MAIRA-2. No self-hosted LLMs.
No 120 GB downloads. The "hardcore engineering" is the cross-validation
logic, not model zoo cosplay.

6.1 THE CORE IDEA -- SILK-SMOOTH CROSS MATCHING
--------------------------------------------------------------------------------
Two independent models look at the same lung image crop:

  MODEL 1 (CNN):  DenseNet-121 (2D, torchvision pretrained, ~30 MB)
                  -- why CNN: spatial texture features, cheap, battle-tested
                     in medical imaging, tiny, runs anywhere.
  MODEL 2 (ViT):  ViT-S/16 (timm 'vit_small_patch16_224', ~22 MB)
                  -- why ViT: global attention catches shape/context the
                     CNN's local kernels miss. Different inductive bias =
                     genuinely independent second opinion.

  Both are fine-tuned on the SAME LUNA16 crops (Stage B prep below).

  CROSS-MATCHING RULES (the actual product logic):
    a. Both agree malignant-ish  (avg p >= 0.7, |p_cnn - p_vit| <= 0.2)
         -> verdict "suspicious", confidence HIGH
    b. Both agree benign-ish     (avg p <= 0.3, |p_cnn - p_vit| <= 0.2)
         -> verdict "likely benign", confidence HIGH
    c. Disagreement (|p_cnn - p_vit| > 0.2)
         -> verdict "inconclusive -- models disagree", confidence LOW,
            ALWAYS escalate to "show this to a radiologist"
    d. Borderline zone (0.3 < avg p < 0.7)
         -> verdict "indeterminate", recommend follow-up imaging per
            Fleischner (pulled from Phase 4 RAG, cited)

  This agreement/disagreement pattern IS the sellable engineering story:
  "ensemble cross-validation of heterogeneous architectures (CNN vs ViT)"
  -- great resume line, trivial to implement, honest to users.

6.3 STAGE B -- DATA PREP FOR BOTH MODELS (1 week, CPU-only, laptop-friendly)
--------------------------------------------------------------------------------
One preprocessing pass feeds BOTH networks. Keep it small on purpose.

  B1. Data: LUNA16 SUBSET ONLY -- annotations CSV + 150-300 scans.
      (Full set is ~120 GB; you need maybe 8-12 GB. Crop-and-throw-away.)
  B2. Preprocess on laptop (SimpleITK, CPU, hours not days):
        - Read MHD/DICOM -> HU window [-1000, 400]
        - 64x64x3 crops around each annotated nodule center
          (3 adjacent slices as channels = pseudo-3D, feeds 2D models)
        - Negative crops randomly sampled, 1:3 positive:negative
        - SAVE AS PNGs in data/luna16_crops/{pos,neg}/ -- simpler than
          npz, viewable, dataloader-trivial
        - SPLIT BY PATIENT (SeriesInstanceUID), NEVER by crop.
          The #1 fake-metrics mistake. 70/15/15 train/val/test.
  B3. scripts/prep_luna16.py -- idempotent, logs crop counts per split.

  DONE WHEN: crop folders populated, split list committed as CSV,
  counts printed and sanity-checked.

6.4 STAGE C -- TRAIN BOTH MODELS ON COLAB (1 weekend + iteration)
--------------------------------------------------------------------------------
Train in the SAME Colab notebook run, back-to-back, same data, same splits.
Track both in one Weights & Biases project.

  Shared recipe (both models):
        - AdamW, lr 1e-4 head / 1e-5 backbone, cosine schedule
        - 20-30 epochs, batch 64, mixed precision, early stop on val AUC
        - Augmentation: horizontal flip OK, rotation +/-15 deg, intensity
          jitter. NO vertical flip (breaks anatomy), NO heavy color aug.
        - class weights for 1:3 imbalance; report AUC not accuracy

  CNN:      timm 'densenet121' (or torchvision densenet121), new head = 1
  ViT:      timm 'vit_small_patch16_224.augreg_in21k', new head = 1

  Target: BOTH models AUC > 0.85 on the held-out patient-level test split.
  If the CNN hits 0.87 and ViT hits 0.86 -- PERFECT. Similar-but-not-identical
  is exactly what makes cross-matching meaningful.

  DONE WHEN: two checkpoints downloaded locally, W&B runs logged,
  test AUC documented for each in MODEL_CARD.md.

6.5 STAGE D -- CROSS-MATCHING ENGINE + SERVING (1-2 weeks, pure CPU)
--------------------------------------------------------------------------------
This is the "hardcore engineering" part and it is 100% local CPU work.

  D1. Export both models to ONNX (opset 17):
        torch.onnx.export -> onnxruntime.quantization quantize_dynamic INT8
        -> app/models_store/densenet121_int8.onnx (~8 MB)
        -> app/models_store/vits16_int8.onnx     (~9 MB)
        Verify AUC drop from quantization < 0.01 for each.

  D2. app/services/crossmatch.py -- THE ENGINE:
        class CrossMatchEngine:
            - loads both ONNX sessions at startup (single-thread, CPU EP)
            - predict(crop_np) -> {"cnn_p": float, "vit_p": float,
                                   "verdict": str, "confidence": str,
                                   "delta": float, "disclaimer": str}
            - implements rules a-d from 6.1 verbatim
            - logs p50/p95 latency per model

  D3. POST /detect/nodule endpoint:
        - reuse Stage A upload storage + modality gate
        - accept 1-3 CT slices (PNG/JPEG/short NPY), run preprocessing
          inline (same HU window + 64x64x3 as training -- import the
          SAME function from a shared module, never re-implement)
        - response: cross-match verdict + Fleischner follow-up text from
          Phase 4 RAG + disclaimer, every time.

  D4. MODEL_CARD.md: data source, split strategy, per-model AUC/sens/spec,
      cross-match confusion behavior, limitations, intended use,
      "research/educational only" positioning.

  D5. Optional polish (only if time remains): simple Grad-CAM overlay
      from the CNN branch for the frontend -- one afternoon, big demo WOW.

  STAGE D DEFINITION OF DONE:
    [ ] Both ONNX INT8 models served, quantization AUC delta < 0.01
    [ ] Cross-match verdicts match rules a-d exactly (unit-tested with
